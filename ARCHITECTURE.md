# Архитектура мастер-бота для управления множественными сообществами

## Проблема (было)
Ранее бот был привязан к одному сообществу через настройки `VK_TOKEN` и `VK_GROUP_ID`. Это не позволяло управлять несколькими сообществами одновременно.

## Решение (стало)
Внедрён **CommunityManager** - мастер-бот, который:
- Не привязан к конкретному сообществу
- Получает токены от разных сообществ через API или команды
- Управляет каждым сообществом через отдельный поток LongPoll
- Хранит токены в базе данных в таблице `platform_accounts`

## Компоненты

### 1. CommunityManager (`managers/community_manager.py`)
Основной класс для управления множественными сообществами.

**Ключевые методы:**
- `register_community(community)` - регистрирует новое сообщество
- `unregister_community(group_id)` - удаляет сообщество из управления
- `publish_to_community(group_id, post_data)` - публикует пост в конкретном сообществе
- `get_community_list()` - возвращает список всех управляемых сообществ
- `run()` - запускает прослушивание событий для всех сообществ

### 2. CommunityAccount
Структура данных для представления сообщества:
```python
@dataclass
class CommunityAccount:
    id: int
    platform: str          # "vk"
    account_id: str        # ID группы в виде строки
    access_token: str      # Токен доступа
    group_id: int          # ID группы VK
```

### 3. База данных
Таблица `platform_accounts` хранит информацию о всех подключённых сообществах:
- `id` - первичный ключ
- `platform` - платформа ("vk")
- `account_id` - ID аккаунта/группы
- `access_token` - токен доступа
- `config_json` - дополнительные настройки (JSON)

## API Endpoints

### GET /api/communities
Возвращает список всех зарегистрированных сообществ.

**Ответ:**
```json
{
  "communities": [
    {
      "id": 1,
      "group_id": 12345678,
      "platform": "vk",
      "account_id": "12345678",
      "active": true
    }
  ]
}
```

### POST /api/communities/register
Регистрирует новое сообщество.

**Параметры:**
- `token` (string) - токен доступа сообщества
- `group_id` (integer) - ID группы VK

**Ответ:**
```json
{
  "success": true,
  "group_id": 12345678,
  "message": "Сообщество 12345678 успешно зарегистрировано"
}
```

### DELETE /api/communities/{group_id}
Удаляет сообщество из управления.

### POST /api/publish/vk/{post_id}
Публикует пост в сообществе.

**Параметры:**
- `post_id` (path) - ID поста в базе данных
- `group_id` (query, optional) - ID целевого сообщества. Если не указан, используется первое доступное.

**Ответ:**
```json
{
  "success": true,
  "post_id": 123,
  "group_id": 12345678,
  "platform_post_id": 456789,
  "url": "https://vk.com/wall-12345678_456789",
  "status": "published"
}
```

## Управление через сообщения бота

### Команда /add_token
Добавляет новое сообщество прямо из диалога с ботом.

**Формат:**
```
/add_token <токен> <group_id>
```

**Пример:**
```
/add_token abc123def456 12345678
```

### Другие команды
- `/start` - приветствие и список команд
- `/status` - статистика постов (по всем сообществам)
- `/generate` - создать пак постов на неделю
- `/approve` - одобрить последний черновик

## Как это работает

1. **Запуск приложения:**
   - При старте FastAPI создаёт экземпляр `CommunityManager`
   - Менеджер загружает все сообщества из базы данных
   - Для каждого сообщества запускается отдельный поток с LongPoll

2. **Получение сообщений:**
   - Каждое сообщество имеет свой собственный LongPoll цикл
   - Сообщения обрабатываются независимо для каждой группы
   - Бот отвечает от имени того сообщества, которому написал пользователь

3. **Публикация постов:**
   - При публикации указывается `group_id` целевого сообщества
   - Менеджер использует соответствующий токен для API вызова
   - Пост публикуется от имени указанного сообщества

## Преимущества новой архитектуры

✅ **Масштабируемость** - можно добавить неограниченное количество сообществ
✅ **Изоляция** - каждое сообщество работает в своём потоке
✅ **Гибкость** - токены можно добавлять/удалять динамически
✅ **Надёжность** - ошибка в одном сообществе не влияет на другие
✅ **Единая точка управления** - все сообщества контролируются из одного интерфейса

## Миграция со старой версии

1. Старый бот (`bots/vk_bot.py`) больше не используется
2. Перенесите текущий токен и group_id через API:
   ```bash
   curl -X POST http://localhost:8000/api/communities/register \
     -d "token=ВАШ_ТОКЕН" \
     -d "group_id=ВАШ_GROUP_ID"
   ```
3. Обновите конфигурацию - поля `vk_token` и `vk_group_id` в `.env` больше не обязательны

## Пример использования

```python
from managers.community_manager import CommunityManager, CommunityAccount

# Создаём менеджер
manager = CommunityManager()

# Регистрируем первое сообщество
community1 = CommunityAccount(
    id=0,
    platform="vk",
    account_id="12345678",
    access_token="token1",
    group_id=12345678
)
manager.register_community(community1)

# Регистрируем второе сообщество
community2 = CommunityAccount(
    id=0,
    platform="vk",
    account_id="87654321",
    access_token="token2",
    group_id=87654321
)
manager.register_community(community2)

# Публикуем пост в первое сообщество
result = manager.publish_to_community(12345678, {
    "text": "Привет, мир!",
    "image_path": "/path/to/image.jpg"
})

# Запускаем прослушивание событий
manager.run()
```

## Безопасность

⚠️ **Важно:**
- Токены хранятся в базе данных в открытом виде - обеспечьте защиту БД
- Используйте токены с минимально необходимыми правами
- Ограничьте доступ к API аутентификацией
- Команда `/add_token` должна быть доступна только администраторам
